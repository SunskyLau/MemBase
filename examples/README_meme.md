# MEME 三个原生基线的运行方式

从 `agent-memory` 目录分别在三个终端执行：

```bash
./MemBase/examples/evaluate_in_context_on_meme/run_gpt4o_mini.sh
./MemBase/examples/evaluate_dense_on_meme/run_gpt4o_mini.sh
./MemBase/examples/evaluate_md_flat_on_meme/run_gpt4o_mini.sh
```

末尾加 `--dry-run` 可检查配置，不调用模型。绝对路径也可从任意目录执行。每个目录另有 `run_qwen3_30b.sh`，使用 qwen3-30b-a3b-instruct-2507 构建和回答，评判和嵌入仍使用相同 GPT 服务配置。模型、模式和运行编号在具名脚本顶部填写，其余参数沿用 `run.example.sh`。接口地址和密钥只从 `envs/.env` 或环境变量读取。

新结果分别位于 `experiments/meme_<方法>/runs/gpt-4o-mini_core_01_gpt/` 和 `experiments/meme_<方法>/runs/qwen3-30b-a3b-instruct-2507_core_01_qwen/`。末尾服务配置后缀保留原有规则。旧 `run.sh` 和旧结果目录不变，已有实验继续使用原入口续跑；新实验使用上述具名脚本。模型、实验范围或其他配置发生改变时，应使用新的运行名称。

## 固定配置与范围

核心模式先跑无填充版本的两个完整样本，再跑 filler32k 全部 100 个样本。正式主成绩只读 `full/filler32k/summary.json`，不要把两个预检样本混入主表。该版本含 494 个变化前问题和 694 个变化后问题，两个领域各 50 个样本。

三个基线均使用 gpt-4o-mini 构建和回答，gpt-4o-2024-11-20 评判；实际不需要语言模型构建的完整上下文和稠密检索不会额外调用构建模型。温度固定为官方的 0；默认不指定随机种子，显式传 `--seed` 才会实际转发并保存。样本并发 4，评判样本并发 4，每样本评判并发 8。

三者统一使用官方记忆基线的回答提示；这会改变完整上下文基线原有的回答提示，须在论文中披露。其他原生参数不变：回答输出上限 500 词元（tokens）；MD-flat 内部输出上限 2000 词元（tokens）、最多五轮工具调用；稠密检索使用 text-embedding-3-small、检索数量 5、分块 4096 词元（tokens），超长块使用官方 8000/400 滑窗。最终证据不再额外裁剪，完整上下文保留对应观察点的全部对话。

不因输出截断而扩大上限。确实截断的输出保存到调用日志，不能当作完整答案或有效工具参数。结构错误和暂时接口故障最多额外重试两次，底层客户端不重复重试。未修改官方仓库文件。

建立连接最多等待 5 分钟；读取响应、写入和连接池等待保留 10 分钟。这些是各阶段的超时设置，不是整个样本的总时长限制；含重试的累计等待可能更长。构建、检索、回答、嵌入和评判共用此设置。

## 恢复与故障

MD-flat 和稠密检索每完成一个会话保存检查点（checkpoint），变化前、变化后状态分别保存；每题回答、评判各自保存。中断后重新执行同一脚本，会复用已完成内容，不重新生成过去观察点的答案，也不重复调用已经取得终态的问题。

检索、回答或评判的可恢复错误记录为技术失败，按零分进入原定分母；不使用程序编造的拒答文本代替模型回答。评分失败保留真实答案，不能冒称评判模型判错。基础构建失败保留已完成会话，其他独立样本继续，但该阶段不报告完成。凭据、配置、存储和程序错误仍须停止并处理。

合法的“不需要写入新记忆”不视为 MD-flat 错误。摄入完成有效工具操作但用满五轮时保留官方结果并标记警告；检索没有完成输出时不能伪装成“未找到相关事实”。有技术失败或上述警告时，最终状态为 `complete_with_warnings`，需查看失败数后再判断结果是否可用于论文。

## 结果与成本

每个阶段保留 `outputs/`、`judge/`、`audit/` 和 `logs/`。`audit/<样本>/<用途>/requests.sqlite` 是累计请求账本；同目录的 `requests.jsonl` 保存实际输入、输出、终止原因及参数。保留完整上下文、MD-flat 检索工具轨迹、记忆快照和逐题耗时。

汇总包含六类任务、领域、级联/信息缺失的 1/2 跳、变化前正确率、原定题数、实际回答/评分数和技术失败数。变化前的精确召回补做官方确定性匹配；级联、信息缺失与删除继续使用官方平凡通过过滤（trivial-pass filtering）。

费用按构建、检索、回答、嵌入、评判分开统计，包含所有已登记尝试；未知用量明确保留，因此已知词元数可能只是下界。评判费用不计入方法本身费用。输入缓存用量另存，不能重复累加。没有服务商实际价目表时，金额保持未知，不将第三方接口按 OpenAI 标价冒充实际账单。请求累计耗时不等于并发墙钟时间，`execution_times.jsonl` 分别保留每次阶段运行的墙钟时间。

## 环境与直接相关的离线检查

三个专用环境为 `membase-meme-incontext`、`membase-meme-dense`、`membase-meme-mdflat`，使用同一份 `envs/meme_requirements.txt`；实际依赖版本记录在 `envs/meme_requirements.lock.txt`。无需 GPU、独立数据库或本地模型。分词文件共用 `data/cache/tiktoken`，不为每次运行重复下载。

从 `MemBase` 目录执行：

```bash
conda run --no-capture-output -n membase-meme-incontext python -m unittest tests.benchmarks.test_meme_runtime -b -q
```

这组测试使用模拟接口，覆盖三个官方流程、前后顺序与续跑、固定输出上限、评分故障、并行入口和成本归属；不代表真实接口稳定性或正式准确率已经验证。运行前可在任意目录对上述三个脚本分别执行 `--dry-run`。
