# ClaimMem：多层派生记忆的构建、维护与检索

ClaimMem 将对话保存为可追溯的来源（Source），从中抽取原子事实（AtomicFact），再通过直接依赖关系（DependencyLink）逐层形成可复用主张（Claim）。原子事实与主张共用记忆版本（MemoryVersion）、身份协调和更新机制；支持来自原文还是其他记忆，是二者的主要区别。

系统不预定义实体或关系类型，不将条件句编译为专门规则，也不单独保存变化事件主张。变化通过版本修订表达，推理时展开前后版本及其证据。已有依赖由程序局部维护，尚未记录的关系由局部检索与大语言模型（LLM）发现。

```text
消息与公开输入协议 → 来源保存与原子事实抽取 → 统一版本协调
                                            ↓
                        影响发现 → 局部依赖生成与验证
                                            ↓
                        提交变化 → 依赖重算 → 批量修复
                                      ↑          │
                                      └──────────┘

用户查询 → 固定可见快照 → 需求分解与检索
         → 当前／历史／集合解析 → 完整证据路径 → 回答
```

## 输入与执行约定

每个用户、独立对话集合或评测样本使用独立的 `namespace`。来源、版本、依赖、索引、缓存和操作日志都受同一隔离范围约束，不跨样本共享用户记忆。来源按输入协议给出的顺序摄入；公开的时间、事实序号和更新优先级可以使用，但不能从隐藏的任务标签推断处理方式。

系统提供三个接口：

```text
ingest(messages, namespace, input_policy)
flush(namespace, source_cutoff) -> snapshot_id
answer(query, namespace, snapshot_id, query_time) -> AnswerResult
```

`input_policy` 只描述可公开获得的说话者、时间和更新约定。`source_cutoff` 限制本次允许看到的消息，`snapshot_id` 固定已提交的来源与维护结果，`query_time` 解释问题中的“现在”“上个月”等时间。缺少真实日期时保留输入先后关系，不能将运行程序当天的日期代入。

消息批次不能跨越评测观察点。第一版在每个命名空间内同步摄入、单写者提交；`flush` 完成当前批次写入、已有依赖的程序重算及对应检索索引更新后，才发布读取快照。快照可以包含明确的语义修复未完成状态，但不能包含部分提交的支持路径，也不能把旧索引当作已经更新。读取、分页、原文回退和统计均执行相同的可见性过滤，不能通过索引提前看到未来消息。

抽取、协调或索引更新发生技术失败时，按既定次数重试或拆分输入；仍失败则标记该批次未完成，不把旧快照冒充已处理最新消息的状态。已有来源保留，实验记录失败及成本，不静默跳过或从统计分母中删除相关样本。第一版不实现后台恢复调度；技术故障按统一实验规则重跑，语义修复预算耗尽则保留原有 `incomplete` 结果，不能因答案不理想而追加尝试。

评测问题只进入读取阶段，问题、答案和读取时的临时推理不自动写回长期记忆。相同快照上的不同问题相互独立。真实应用中需要保存交互时，另行通过 `ingest` 写入，并保留其来源与生成方式。

## 模块一：来源保存、原子事实抽取与统一版本协调

### 来源与原子事实

系统先保存完整消息，再以最多 `b_memory` 条消息、`max_batch_tokens` 个 token 组成抽取批次。原文索引优先按消息或对话轮次组织；超长内容按连续片段拆分，每片不超过 `max_source_chunk_tokens`，保留原始位置与邻接关系。抽取失败或遗漏不能导致原始内容丢失。

每批附带此前同会话的 `w_context` 条消息，消歧失败时倍增至 `w_context_max`，同时受 `max_context_tokens` 限制。抽取器只从待处理消息生成事实；历史上下文用于指代和相对时间解析，所用片段必须登记。仍无法确定时保留原文与未解析记录，不猜测人物、时间或状态。同批后续更正单独抽取，不直接改写先前陈述。

每条事实只表达一个能够独立变化的命题，保留否定、数量、条件、对象、适用范围和模态。事实来源绑定具体原文片段，而不是只绑定整段摘要。

```text
Source
├── id / namespace
├── message_id / conversation_id
├── speaker / role                     # 保留真实说话者及输入协议中的角色
├── content / source_order / mention_time
└── generation_refs                    # 本系统生成内容的原始依据；其他来源为空

MemoryVersion
├── id / namespace / memory_key / content
├── valid_time                         # 时间点、区间或未知，保留精度
├── modality                           # asserted / uncertain / planned /
│                                      # conditional / hypothetical
├── created_at
├── revision                           # 首次记录可为空
│   ├── previous_version_id
│   ├── reason                         # update / correction /
│   │                                  # reconfirmation / override
│   ├── effective_time
│   └── evidence_refs
└── status                             # active / stale / superseded / deleted；缓存
```

`mention_time` 表示消息何时出现，`valid_time` 表示命题何时成立，`created_at` 表示系统何时写入。后到达的历史信息不能仅因写入较晚覆盖当前状态；计划或可能性不能提前替代已确认状态，也不能到期后自动视为已经发生。

所有说话者的消息均可保存，但必须区分“某人说过 X”和“X 是当前事实”。助手的建议不能自动变成用户的行为或属性；对用户状态的转述也不自动成为新的真值支持。本系统对派生结论的复述不能形成独立来源支持：能够追溯时沿 `generation_refs` 保留原依赖，无法追溯时只支持“助手曾作此回答”。用户之后的明确确认可以作为新的来源。

`role` 由输入协议解释，不能把双人对话的第二位说话者自动视为助手。引用文本、外部内容或助手复述中的“删除”也不能直接成为具有权限的控制操作。来源内容作为待处理数据，不能改变控制权限、字段白名单或系统指令。

### 稳定身份与版本协调

事实与主张使用同一协调器。新内容通过 `reconcile` 模式检索已有有效、陈旧及相关历史版本；候选携带 `memory_key`、内容、范围、时间、状态及必要来源。同批已经暂存的版本也进入候选，避免一次调用内部重复创建身份。

LLM 只能选择候选中的已有 key，或申请创建新身份：

```text
REUSE(existing_memory_key)
NEW(identity_description)
```

`NEW` 使用内容与身份描述再执行一次有界身份复查，复用现有检索器，不递归重试。真实 `memory_key` 由程序分配稳定标识；可读名称只是标签，不以 LLM 生成的字符串作为身份等值依据。程序校验所有被选择的标识属于当前候选与命名空间。

`memory_key` 表示同一项可修订记忆，不是预定义槽位。身份判断考虑人物、对象、作用范围、时间和模态。“喜欢餐厅 A”和“喜欢餐厅 B”通常是可并存命题，不能因为都属于餐厅偏好而互相替代。时间不同但描述同一持续状态的记录可以属于同一版本族。

协调器提出新增、补充来源、修订、撤回、删除或保留冲突。先判断是否描述同一状态与重叠范围，再应用公开的更新优先级和明确陈述；仍无法决定时保留冲突，不一律取最新，也不一律拒绝更新。模型常识不能覆盖输入协议明确要求采用的新事实。

同一命题在同一适用时期被再次陈述时，复用版本并增加来源支持；同一来源重复摄入保持幂等。不同发生时间的重复行为不是重复事实，例如两次就餐不能因为句子相同被合并成一次。旧版本已经关闭后，再确认相同内容需要创建新的适用时期。

```text
update          现实状态发生变化，可用于触发变化条件。
correction      先前信息有误，不构成一次真实世界变化。
reconfirmation  关闭之后重新获得可靠确认，不复活旧时期。
override        按公开优先级替换当前知识，不额外声称现实发生过变化。
```

“发生变化时”的推理接受两种依据：原文明确陈述的变化事实，或证据确认的 `reason = update` 修订。仅有首次出现的新值不能推出发生过变化；但“今天搬到了台中”本身就是有来源的变化事实，即使旧住址未知，也可以作为普通原子事实使用，不新增事件类型。来源补充、纠错和单纯优先级覆盖不能冒充真实变化。修订证据必须可展开；历史新信息按实际时间放入版本族，不强行接在最新现实状态之后。修订依据后来被推翻时，追加记录停用该变化解释并重审其下游；新值若有其他直接支持，不因旧值错误而自动失效。

版本内容与修订元数据保持不变。内容、模态或适用时期发生语义变化才创建版本；支持路径与可用状态变化不创建内容版本。后续关闭、纠错、删除和冲突解决通过追加记录与操作日志表达，状态缓存可以重建。

事实按消息及原文顺序协调。独立内容可以批量判断，同一状态的连续变化保留顺序；`A → B → A` 不能压缩成“没有变化”。修复读取相应变化时点的来源前缀，不能使用批次后面才出现的内容作为提前已知的依据。

## 模块二：统一检索、影响发现与多层依赖生成

### 统一检索

```text
Retrieve(queries, mode, mandatory_context, snapshot, budget)

mode = reconcile / derive / validate / read / history / aggregate / source
```

每个查询分别取得稠密语义检索前 `k_dense[mode]` 项、BM25 稀疏检索前 `k_bm25[mode]` 项，排除 BM25 分数为零的结果，以倒数排名融合（RRF）合并。时间明确时补充至多 `k_time[mode]` 条相关记录。时间过滤不应机械排除时间未知但可能相关的来源。

每轮查询结果去重后最多保留 `max_candidates[mode]` 条语义候选。该参数限制一轮候选页，不是整个问题的完整结果集合。合并时覆盖不同触发对象或回答需求，不设事实与主张的固定配额，也不设置统一语义相似度硬阈值。

已知结构上下文不参加语义 Top-k 竞争，包括相关版本族、被改变的前提、支持与失效关系、修订证据和明确冲突。状态重算遍历完整相关结构；LLM 每次仅读取需要验证的完整路径与目标，超出 `max_context_tokens` 时拆分处理。单条必要路径仍超限则标记未完成，不能静默截掉关键前提。

来源检索覆盖完整已摄入消息，不仅覆盖成功抽取出的片段。命中后按需补充相邻对话，邻接展开、结构展开和来源文本均计入输入及证据成本。

### 已知依赖维护与未知影响发现

新增事实、修订、撤回、删除和待修复目标均可触发局部处理。对修订使用“旧内容 + 新内容 + 修订原因”检索，不能只使用新值。已知依赖由反向索引直接定位；即使没有已知下游，语义变化也要进入有界的局部影响发现。

例如，旧通勤时间可能只有直接来源支持。住址变化时，程序无法单靠支持图发现它过期，需要召回“通勤随住址变化”及旧通勤值，形成失效判定。检索到明确条件但缺少目标或必要前提时，允许至多 `max_gap_queries_per_call` 个定向补检；补检结果只提供候选，不自动成为依赖。

额外的开放式推理需求最多为 `q_max` 个，默认关闭。`q_max = 0` 不禁止针对已识别证据缺口的定向补检。所有补检共享候选、上下文与调用预算，不能无限探索。

影响发现使用完整的新来源、条件与状态，不依赖 benchmark 的根节点或黄金边。没有召回关系不等于关系不存在；日志区分“未发现影响”和“已经验证某目标不受影响”。

### 多层主张与直接依赖

生成器提出有界无环的局部图。主张可以引用原子事实、已有可用主张和本轮较早提出的临时主张：

```text
F1 + F2 + F3       → C1
C1 + F4            → C2
C2 + C3 + F5 + F6 → C4
```

每次最多提出 `max_claims_per_call` 条主张、`max_dependencies_per_call` 条依赖，每条依赖包含 `1～max_premises_per_dependency` 个直接前提。候选应形成多前提组合、更新后的结论、范围明确的偏好或跨会话归纳，而不是单条事实的同义复述。允许不生成主张。

从有限记录归纳时，主张必须保留所覆盖的记录范围或固定时间范围，不能把局部召回扩展为“当前全部”“最近几次”“从未”等开放范围结论。例如三次已记录的素食就餐可以支持对这三次行为的总结，不能自动推出永久有效的“最近三次均吃素”。依赖全量集合的最新汇总优先由 Reader 计算；持久化时只保存范围明确、证据充分的结论。用户直接表达的偏好和可由当前前提支持的状态主张仍正常保存，不要求所有主张都改成历史摘要，也不增加集合范围监听机制。

```text
DependencyLink
├── id / namespace
├── premise_refs
├── effect                             # SUPPORT / INVALIDATE
├── target_version_id
├── effective_time                     # INVALIDATE 的关闭生效时间
└── created_at

PremiseRef
├── type                               # SOURCE / CURRENT / HISTORICAL
├── id                                 # Source 或具体 MemoryVersion
├── span / context_refs                # SOURCE 使用；包含必要消歧片段
└── at_time                            # HISTORICAL 使用；可为明确的先后边界
```

`SOURCE` 引用具体原文及必要消歧片段。直接事实由来源支持；使用多条来源进行推断时，应先记录相应原子事实，再建立派生依赖。不得把未声明的外部假设作为持久化用户结论的隐含前提。

`CURRENT(m)` 要求指定版本在本次求值时适用。`HISTORICAL(m, t)` 要求该版本在 `t` 有成立依据，不只是记录存在。普通后续更新不抹去过去事实，纠错、撤回或删除则可能改变其证据可用性。来源消歧片段和修订证据也登记反向引用，避免出现未记录的依赖。

所有引用绑定具体版本，不能沿 key 自动重绑到内容相同的新版本。持续依赖使用 CURRENT，一次性触发的依据按实际触发时间使用 HISTORICAL；不能因为某条旧政策后来停止适用，就自动撤销它过去已触发的结果，也不能仅凭历史事件推出当前状态。

一条 SUPPORT 内的前提构成与关系（AND），同一目标的多条 SUPPORT 构成或关系（OR）。一条路径失效，其他有效路径可以继续支持未被关闭的结论。OR 不代表来源统计独立，重复转述不能计成新的独立依据。

INVALIDATE 表示前提足以说明旧版本从某时点起不再可靠。它是有证据的适用期关闭，不是随前提现状反复开关的否决。已经获得明确新值时，通过统一版本协调建立修订，不为同一次替代重复创建失效关系；没有可靠新值时才关闭旧值并保留未知。

生成的结论必须保留条件和范围。例如“父亲不能长距离步行、酒店距地铁 2km、没有接驳车”可以支持“主要依靠步行往返地铁时，该酒店不符合父亲的出行限制”，不能直接支持“该酒店在所有情况下都不适合”。

## 模块三：验证、批量修复与版本维护

### 验证与幂等提交

候选主张和纯失效操作都通过 `validate` 模式检索反向证据；相关版本、冲突和来源直接展开。验证器复用模块一的身份选择契约，并检查前提充分性、来源归属、人物与时间一致性、模态、失效目标、适用范围和已召回反例。

充分性是硬约束，简洁性是优化目标。验证器可以删除冗余前提，或拆分各自充分的支持路径，不要求求解全局最小证明。使用中间主张时，必须检查所用路径的原子事实和来源，不能只核对结论文本。算术和日期运算在操作数、单位与时间范围明确后由程序核算，并保留来源。

临时图按拓扑顺序验证，上层只能引用已通过的下层。归并为真实标识后，再检查全局图、深度、可见快照和提交后一致性。SUPPORT、INVALIDATE 及修订证据的实际依赖均纳入环检查，版本导航指针本身不充当支持。目标的内容作为验证上下文，不应把目标当前有效性写成否定它自己的前提。

新值不能依赖一个会被它自己替代掉的 CURRENT 前提；确需旧值时使用有时间依据的 HISTORICAL 引用。同一有效期内的自我支持、派生回写造成的循环和依赖之间的攻击均拒绝。

`max_claim_depth` 限制完整支持路径的派生层数：来源支持的原子事实为第 0 层，每次记忆间派生增加一层。已有后继和历史引用也参与深度检查，不能通过重新命名或新批次重置深度。超限不丢弃新来源，也不保留已经过期的旧结论；可以读取时从证据重新计算，但不冒充已成功维护的持久化主张。

依赖解析为真实标识后，以结构签名幂等写入：

```text
signature(D)
= namespace + effect + target_version_id + effective_time
  + sort(normalize(premise_ref) for each premise_ref)
```

来源位置、时间引用和上下文引用均属于规范化前提。来源补充、重复调用和重试不能产生相同依赖的多个副本。支持集合变化不创建内容版本。

采用批量推理、单写者提交。程序在提交前再次检查前提、目标和版本族是否仍与处理快照一致；不一致的目标重新排队。共享前提的依赖组整体校验与提交，不能让下游引用尚未提交或验证失败的上游。

### 当前性、失效与历史

```text
Supported(M, t, s) = 在快照 s 下，存在一条支持路径适用于时间 t
Closed(M, t, s)    = 在该范围已有生效的替代、失效或纠错关闭
Usable(M, t, s)    = Supported 且非 Closed，且未被删除、
                    未处于待修复或尚未解决的冲突中
```

`status` 是上述判断的缓存，不是独立真值来源。当前查询检查查询时间，明确到期的状态即使没有新消息也不能继续使用。过去事件只要没有被推翻，仍可以是当前认可的记忆；“发生于过去”不等于“已经过时”。状态按适用区间判断，事件按问题要求的发生时间检索，不要求事件发生于查询当天。

失去全部支持但尚未被关闭的版本进入陈旧状态，获得可靠支持后可以恢复。已经被替代或显式失效的旧版本不能因为触发条件后来消失就自动恢复，需要重新验证并创建新的适用时期。

INVALIDATE 在提交时记录证据、快照与生效范围。普通后续更新不撤销其关闭效果；其证据被纠正或删除时触发复核，未完成前不自动恢复目标。系统不实现“否决的否决”，而是通过新的验证结果和追加的控制记录修正可用时期。

历史读取从版本族收集所需记录，按成立时间、显式修订与已知先后关系还原，不能只按创建时间排序或只沿一条指针丢掉分支。区分“依据目前信息，过去是什么”和“当时系统知道什么”；后者还限制来源与操作快照。

### 批量修复队列

```text
memory_key        → memory_version_ids
premise_ref       → dependency_ids
source/context_ref→ 引用该来源的事实、修订与依赖
target_version_id → dependency_ids
```

每次变化通知旧版本、新版本和相关版本族的引用。队列优先处理显式控制操作、已有依赖重算、受影响结论修复，最后处理可选归纳。结构重算本身不调用 LLM，不因另一条独立支持仍然有效就忽略新证据对整体结论的否定。

```text
提交来源或变化
    → 重算已知依赖；局部检索潜在影响
    → 暂停已确认可能过期的目标
    → 收集同一快照下的就绪修复目标
    → 批量生成、验证与提交
    → 新变化继续进入队列
```

同一快照下不存在冲突的就绪目标可以打包，共享结构证据；每次最多处理 `max_repair_targets_per_call` 个目标，同时受输入、输出和依赖预算限制。兄弟目标可以同批处理；上层依赖尚未修复的目标等待下一轮，或作为同一局部 DAG 按拓扑顺序验证。打包不改变消息的因果顺序，也不意味着并发修改状态。

每个输入目标必须返回一种处置建议：

```text
UPDATED     已提出新内容及其依据，等待验证和提交。
UNCHANGED   重新检查后内容仍成立，给出适用的支持依据。
UNKNOWN     已确认旧值失效，但现有证据无法推出新值。
DEFERRED    缺少证据、预算或尚未完成，记录未完成目标。
```

这些是任务结果，不是新的记忆状态；UPDATED、UNCHANGED 和 UNKNOWN 都需验证。目标遗漏、格式损坏、输出截断或未通过验证不能默认为 UNCHANGED 或 UNKNOWN。抽取、生成或验证超限时，优先按来源范围或独立目标拆分，不能直接截取半份输出作为完整结果；重试仍失败则记录未完成范围。已关闭版本即使得到相同内容，也按重新确认写入，而不是原地恢复。

`max_generation_calls_per_update` 按一个消息批次更新事务中的生成批次计数，包括初始影响判断、派生和修复，不按单个目标计数。协调、验证和重试另计实际成本。相同目标、输入版本、相关证据和处理配置没有改变时，不重复生成；`flush` 不重置同一事务已经消耗的预算。

已有固定依赖图的受影响闭包完整重算，不设置传播跳数上限。新的语义生成受调用和图深度限制。达到预算后，保留待处理目标和 `maintenance_incomplete` 原因，其他不受影响记忆仍可使用。中间变化尚未处理就达到预算时，不把受影响目标视为已经正确覆盖整段变化。

### 级联与信息缺失

例如，已有负责人、条件和旧审查人；新消息确认负责人发生真实变化：

```text
F1：负责人是 Sarah。
F2：如果负责人变化，代码审查人随之改为 Seoyun。
F3：负责人是 Minjun。
    revision = {previous: F1, reason: update, effective_time: t}

F2 在 t 的适用证据 + F1/F3 的真实修订证据
    → C1：该次变化后，当前代码审查人是 Seoyun。
```

验证时将简写展开为具体的 CURRENT、HISTORICAL 与修订证据引用，依据条件原意决定持续适用范围。C1 替代旧审查人信息后进入同一队列，继续发现和修复下游；不能只将旧结论标记陈旧就算完成级联。

若证据只有“通勤时间随住址变化”和搬家事实，没有足够信息计算新通勤时间，则建立针对旧通勤版本的 INVALIDATE。后来再次搬家，不会自动恢复最早的通勤值。UNKNOWN 必须区分已确认失效、证据未召回和维护未完成，不能用统一拒答掩盖处理失败。

### 纠错、撤回与删除

纠错关闭错误结论对应的真实性，不抹去“曾经这样说过”的陈述历史。撤回某一来源只停用该来源的事实支持；其他独立来源仍可成立。明确否定整个结论时才关闭目标，不能把来源撤回自动解释成现实状态变化。

删除是具有权限的显式控制操作，不是普通 INVALIDATE。操作日志保存来源、目标范围、生效顺序和执行进度。范围可以是来源片段、指定版本，或截至删除时刻的一项记忆及其已有来源。删除请求不明确时不任意扩大范围。

删除过滤在所有读取通道执行，包括原文、历史、依赖展开、索引片段和重新抽取。包含被删值的删除指令本身也不能成为泄露或重新写入的来源；正常回答只说明信息不可用，不复述被删内容。混合消息按片段处理，不因删除一句话而无条件移除无关内容。

依赖被删证据的路径失效。其他路径只有在不违反删除范围时才可继续使用；不能以独立来源为由绕过对整项记忆的遗忘要求。用户后来主动重新提供的信息可以形成新版本，不重新利用被删来源。第一版实现逻辑删除，不声称完成备份或模型参数中的物理擦除。

## 模块四：按问题需求读取与证据化回答

### 查询需求与候选覆盖

读取器仅根据问题文本、公开查询时间与已允许的来源选择当前状态、历史、原文复述、多跳或聚合策略，不读取黄金任务类别。复合问题先形成临时回答需求，单轮最多发出 `max_read_queries_per_round` 个查询；未覆盖的需求在后续轮次继续处理，不硬编码问题必须包含几个实体。

普通检索最多 `max_read_rounds` 轮，每轮合并记忆与来源候选。已找到的必要证据按需求保留，不因下一轮更相似的结果而随意丢弃。需要多跳时，优先用当前缺失的关系、对象或条件继续检索，而不是不断改写已经回答的部分。

原文回退补救抽取遗漏，但附带关联记忆的时间、关闭、纠错与删除信息。最终使用某个原文旧值前，补齐已知版本族与控制记录；不能结构化层已经失效，原文层又把同一句话当作无条件当前事实。

### 显式多项问题与开放集合

显式多项问题分别检查每项是否有足够证据。开放集合、计数或全量汇总则维护查询临时累积器：

```text
items                 # 已确认项目及发生身份
item_evidence         # 项目对应的来源与支持路径
visited_source_ranges # 已检查的来源范围与分页游标
unresolved_needs       # 尚未完成的回答需求
stop_reason           # 需求满足 / 范围已遍历 / 预算耗尽 / 检索停滞
```

先用语义检索定位相关内容，需要进一步覆盖时，对问题声明的时间、会话或来源范围进行真实分页扫描。范围没有明确限制时，以该命名空间当前可见来源为范围，不把最初召回的几段内容冒充完整范围。扫描复用来源读取与局部证据提取，不形成新的长期记忆类型。

`max_aggregate_scan_tokens` 限制本次补充扫描的来源 token 总量；每页仍受 `max_context_tokens` 限制。扫描只在来源已穷尽或预算耗尽时结束，不受普通语义查询轮数限制，也不因连续两轮没有新增项目就宣告完整。无需全量覆盖的问题不默认扫描全库。

按问题区分去重单位：“去过哪些餐厅”可按餐厅归并，“去了几次”按发生记录统计。不同时间的同类事件不能误合并，重复摄入同一来源也不能重复计数。计数、金额或日期差先检查操作数和范围，再由程序计算。

来源范围已遍历只是覆盖记录，不是 LLM 零遗漏的证明。预算耗尽、识别不确定或部分需求缺失时，保留已确认结果并标注有限覆盖。`max_candidates` 仅限制候选页，不能把已经收集的集合再按 Top-40 静默截断后声称完整。

### 完整证据路径与输出

召回主张后，沿可用 SUPPORT 展开到原子事实和来源。OR 路径优先选择较紧凑且完整的一条；AND 路径不能删去必要前提。重复来源去重，时间、修订、原文邻接与派生依据都计入 `max_evidence_tokens`。

最终证据超限时，先压缩无关上下文、选择等价较短路径，再按回答需求保留证据。单个结论的必要证据仍放不下时，该结论标为未完成，不能只展示结论而隐藏关键前提。集合无法在预算内完整表示时，不把被截断的项目说成全部。

读取器在固定快照中解析可靠当前值、未知、冲突、删除和未完成。已有有效新值时回答新值；已确认旧值失效且无新值时回答当前未知；检索不足或维护未完成时记录对应原因，不与已确认的信息缺失混淆。读取阶段可以从有效证据进行只读推理，但不修改持久化图，并记录结论是否由 Reader 临时算出。

```text
AnswerResult
├── answer_text
├── resolution_status                 # resolved / unknown / conflict /
│                                     # deleted / incomplete
├── reason                            # 失效无新值、召回不足、预算耗尽等
├── evidence_refs
├── coverage                          # 需求覆盖、来源范围与停止原因
└── read_trace                        # 检索、推理、计算与成本；不作为新记忆
```

当前问题直接给当前值，不并列旧值制造歧义；历史问题才列出相应版本顺序；精确复述优先复制允许访问的原文片段。答案与证据审计分开，正式评分使用 `answer_text`，依赖和证据指标使用审计字段。开放域回答可以使用回答模型的常识，但不能将常识猜测写成用户事实，或覆盖输入明确给出的反事实更新。

## 评测输入、实验对应与验收

### 评测输入隔离

数据适配层只向构建器提供原始消息、真实说话者、公开时间和顺序、统一允许的图像信息，以及无任务含义的来源标识。内部来源标识由程序生成，与原始评测标识的对应关系只在评测侧保存；标签不能通过文件名、ID 后缀或排序进入模型。

问题文本和公开查询日期仅在 `answer` 时提供。答案、黄金证据、任务类型、依赖边、跳数、根节点和生成时的实体清单只用于运行后评分。所有可见信息处理采用字段白名单，不把整个数据集 JSON 直接输入模型。

LongMemEval 中的 `has_answer`、`answer_session_ids`、`question_type` 和题号携带的类别信息不得进入系统。LoCoMo 的 `qa`、人工 `event_summary` 以及预生成 observations/session summaries 不作为主实验输入；需要使用后两者时另列配置。MEME 的 evidence/filler 类型、`evidence_type` 和 `gold_facts` 等辅助字段仅留在评测侧。[^longmemeval][^locomo][^meme-runner]

### 数据集对应

| 数据集 | 核心检验 | 实现与报告要求 |
|---|---|---|
| MemoryAgentBench FactConsolidation-SH/MH | 事实替代、更新后的多跳回答 | 保留公开序号及“新序号优先”的协议；writer 与 reader 一致使用更新后事实；分别报告 SH/MH 和旧值误用 |
| MEME | 精确召回、聚合、跟踪、删除、级联、信息缺失 | 使用 before/after 快照，保留变化前检查；完整报告六项及一跳／两跳传播、未知和删除泄露 |
| LoCoMo | 长期对话细节、多跳、时间与开放域效用 | 主报告第 1–4 类及各类结果，保留原文；使用相同图像表示；原生指标与额外统一 judge 指标分开 |
| LongMemEval-S | 跨会话、知识更新、时间推理、助手侧信息与拒答 | 固定数据版本和 hash；使用公开会话时间与 `question_date`，完整保留允许的用户和助手消息；报告总体及分类结果 |

FactConsolidation 的公开协议要求较大序号代表较新事实，不能另加“必须显式否认旧值才更新”的门槛；MH 不要求预先物化所有答案，也不能用模型旧常识替代当前证据。[^mab]

MEME Aggregation 检查多个目标值的覆盖，系统只能从问题分解需求，不能输入或硬编码黄金实体数。Cascade 必须检验新值是否得到明确推出，不能把一律未知算作成功；Deletion 的回答不能在解释删除时重新暴露旧值。before 查询必须在后续变化尚未摄入时执行，其问题与答案不影响之后的写入。[^meme][^meme-runner][^meme-judge]

LoCoMo 的两位具名说话者均按原始身份处理。图像信息统一使用允许的 caption 或统一视觉处理，不能不同方法获得不同信息。公开评测代码含 token-level F1，因此与额外 LLM 判定准确率分别报告，不将长篇证据审计混入正式短答案。[^locomo][^locomo-eval]

LongMemEval-S 的 `question_date` 和会话时间是时间解释的依据，答案定位标签不是。助手侧内容用于回答“助手曾建议或提供什么”，不能因此成为用户已经执行的行为。[^longmemeval]

### 对照、诊断与成本

主对照依次为“原文检索”“原文 + 统一事实版本管理”“加入派生主张”“完整 ClaimMem”。比较写入时派生与只读推理，分析深度、结构检索、批量修复和集合补扫的边际收益。不因能够生成多层图，就要求每批都生成高层记忆。

所有方法使用相同的可见来源、回答模型、评判模型与最终证据 token 预算。额外扫描和内部推理不能只靠相同最终上下文就声称成本公平；报告写入、维护、检索、扫描、验证及回答的完整调用与 token 成本，并提供预算匹配结果或准确率—成本曲线。

除最终 QA 外，记录身份漏配与误合并、条件与目标召回、依赖验证正确率、修复成功与延期、旧值泄露、集合项目覆盖、来源路径完整性、存储增长和延迟。分别测量写入后的状态正确率与 Reader 临时推理后的答案正确率，不能把读取阶段补救全部算成依赖维护成功。

错误按抽取、身份协调、候选召回、依赖推理、程序维护和最终回答定位。关键结果报告重复运行或置信区间；对同一对话包含多个问题的情况，按独立对话或样本分组统计，不把所有问题当成相互独立的实验。

### 最低回归测试

| 情形 | 必须满足的行为 |
|---|---|
| 同义状态描述与不同对象偏好 | 前者复用身份，后者不误合并 |
| 事实与主张相互替代、相同来源重放 | 使用同一版本机制，重复提交幂等 |
| 助手复述派生结论后上游失效 | 不因复述获得虚假的独立支持 |
| 纠错、优先级覆盖与真实变化 | 只有来源明确的变化或经确认的真实修订触发对应条件 |
| 未知旧值，但原文明确陈述变化 | 保存并使用变化事实，不凭空补出旧值 |
| 已记录行为之后新增一次不同选择 | 固定范围总结仍可读，不将旧总结当作最新全体结论 |
| 同批 `A → B → A` 与分批处理 | 在相同已验证操作序列下保留中间变化与版本语义 |
| 一条支持失效但其他路径成立 | 未整体关闭的结论仍可用 |
| 多个兄弟目标与两跳依赖修复 | 正确打包、逐目标返回结果、保持拓扑顺序 |
| 搬家后无新通勤值，再次搬家 | 旧值不复活，不虚构新值 |
| 相同 Top-k 连续返回但还有未访问来源 | 不宣称集合完整，按范围和预算继续扫描 |
| 重复事件、重复来源与计数 | 发生次数不误合并，同一来源不重复计算 |
| 未来计划、到期状态、乱序历史信息 | 不提前实现、不延续过期值、不按写入顺序改写过去 |
| before 读取与跨样本运行 | 不读未来，不跨命名空间泄露 |
| 删除后从原文、历史、指令或派生路径读取 | 不返回删除范围内的信息 |
| 输入／输出超限、缺项、深度或调用预算耗尽 | 明确未完成，不静默成功、不丢新来源、不继续确定输出旧值 |
| 抽取、协调或索引更新失败 | 不发布冒充完整处理结果的新快照，不静默跳过评测样本 |
| 重复摄入、日志重放与缓存重建 | 对同一已提交操作序列得到一致状态 |

## 设计边界

核心语义记录保持为 Source、MemoryVersion 和 DependencyLink；操作日志保存控制动作、提交顺序与任务进度，索引和状态均可重建。JSON 或数据库只是持久化选择，不改变身份、时间、删除与依赖语义。

第一版以所选四组 benchmark 的顺序摄入、版本更新、有限层级派生和来源化读取为实现范围。不新增自动审计与撤销 LLM 历史决策的引擎、任意时间区间拆分与自动修补、异步索引一致性、长期后台恢复调度或复杂权限历史系统。普通用户纠错、基础时间范围、样本隔离、显式删除和原文过滤仍属于必需语义；其余扩展仅在开发数据暴露实际瓶颈后考虑。

第一版不实现通用规则引擎、任意循环推理、概率信念网络、否决之间的攻击或无限长递推。有限检索不能保证发现所有潜在依赖，固定深度也不能保证物化任意长证明。系统保证程序可检查的引用、提交、可见性与状态约束；自然语言判断和最终性能必须由实验验证，不将验证器通过视为形式证明。

整个系统保持统一分工：LLM 从局部来源中提出事实、身份判断、主张和依赖；程序负责稳定标识、版本提交、证据可见性、依赖重算、批量调度和读取约束。高层记忆是可追溯、可修订的派生结果，原始对话始终保留为受同一控制规则约束的证据基础。
