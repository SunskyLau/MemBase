# OurMem：让派生记忆随事实变化而保持正确

> **当前名称只是临时名称。我们关心的不是如何构造更复杂的记忆，而是如何让智能体已经形成的高层结论，在底层事实变化后仍然正确、稳定并且能够解释。**

这是一份持续演化的研究构想。它只记录当前稳定的问题意识、方法直觉和评测方向，不提前规定最终的数据结构、提示词、索引方式或系统形态。具体设计将在实现和实验中逐步形成。

---

## 1. 研究动机

长期智能体记忆（long-term agent memory）不仅会保存用户说过的事实，也会根据多个事实形成可复用的高层结论。

例如，用户曾经告诉智能体：

- 父亲不能走太远；
- Hotel A 距离地铁站约 200 米。

智能体可能据此形成一条派生声明（derived claim）：

> Hotel A 比较适合父亲出行。

后来用户纠正：

> Hotel A 实际距离地铁站约 2 公里。

许多记忆系统能够更新“200 米”这条事实，却不知道“Hotel A 适合父亲”也需要重新判断。于是，记忆库里虽然已经有了最新事实，智能体仍然可能被旧结论误导。

如果系统选择重新总结一大片相关记忆，又可能误改“母亲不吃辣”“用户喜欢安静酒店”等本来无关的内容。

因此，我们希望记忆系统能够做到：

> **该变化的正确变化，不该变化的保持稳定。**

---

## 2. 核心问题

派生声明（derived claim）不是用户直接说出的原话，而是系统根据若干证据形成的判断。

如果系统只保存派生声明（derived claim）的文本，却不保存它为什么成立，那么当事实变化时，系统就很难知道：

- 哪些派生声明（derived claim）必须重新判断；
- 哪些派生声明（derived claim）仍然拥有其他有效依据；
- 哪些记忆只是主题相关，但不应该被修改；
- 哪些新信息虽然不在旧依据中，却足以推翻旧结论。

实体、关键词和向量相似度可以发现语义相关性（semantic relatedness），但语义相关性（semantic relatedness）并不等于更新依赖（update dependency）。

例如，“Hotel A 的早餐很好”与“Hotel A 适合父亲”在语义上相关，但早餐发生变化，通常不应该触发出行适合性结论的更新。

因此，我们的核心观察是：

\[
\boxed{
\text{语义相关性（semantic relatedness）}
\neq
\text{更新依赖（update dependency）}
}
\]

语义相关性（semantic relatedness）帮助系统发现“可能需要检查什么”，显式成立依据（explicit justification）帮助系统判断“什么事实变化后，这条结论需要重新判断”。

## 3. 方法直觉

OurMem 希望把高层记忆从生成后静置的文本，变成具有成立依据（justification）、能够随证据变化而维护的派生知识（derived knowledge）。

宏观上，整个过程包含四个相互连接的部分。

### 3.1 保存可追溯的事实

对话被整理为能够独立变化的原子事实（atomic fact）。每条原子事实（atomic fact）保留原始出处、时间、涉及对象和当前状态。

用户纠正、撤回或补充信息时，系统能够区分当前事实与历史事实，而不是反复覆盖同一段文本。系统自己的推断也不会被伪装成用户原话。

### 3.2 形成带依据的高层结论

当若干原子事实（atomic fact）能够形成具有复用价值的结论时，系统可以形成派生声明（derived claim），并记录它的成立依据（justification）。

每条派生声明（derived claim）保存一张当前成立依据（justification）。这张依据可以同时引用多条共同必要的原子事实（atomic fact），并在依据发生变化时被新版本替换。

显式成立依据（explicit justification）既用于解释结论，也用于告诉系统哪些事实变化后，相关派生声明（derived claim）需要重新判断。当前依据中的任一必要事实失效后，系统就会重新验证这条结论。

### 3.3 根据变化维护相关结论

新事实到来后，系统可以从两个方向寻找可能受影响的派生声明（derived claim）：

- 沿已有成立依据（justification）寻找明确依赖变化事实的结论；
- 通过实体、时间和语义线索寻找旧成立依据（justification）之外的新限制或新反例。

例如，“Hotel A 没有电梯”并不属于原来的距离依据，却可能推翻“适合父亲”的结论。

系统随后围绕有限候选进行局部维护（local maintenance）。派生声明（derived claim）可能继续保留，也可能被修订、失效或变得不确定。具体动作和判断方式应在实现中逐步探索，而不是由当前文档提前固定。

### 3.4 检索结论、依据和出处

查询时，系统可以同时检索派生声明（derived claim）和原子事实（atomic fact）。

如果返回一条派生声明（derived claim），它还应能够展开当前有效的成立依据（justification），并继续回到原始对话。

最终交给回答模型的内容不只是若干相似文本，而是：

> 当前结论是什么、为什么成立、证据来自哪里、哪些旧信息已经失效。

整个思路可以概括为：

\[
\boxed{
对话
\rightarrow
版本化事实（versioned fact）
\rightarrow
带依据的派生声明（derived claim）
\rightarrow
局部维护（local maintenance）
\rightarrow
证据可追溯的检索
}
\]

### 3.5 可能的混合处理（hybrid processing）

消息（message）到来后，不一定立即触发一次完整的记忆构造。后续可以考虑先将消息（message）放入缓冲区（buffer），再根据会话结束、信息数量或其他自然条件，批量抽取原子事实（atomic fact）。明确而重要的事实变化可以较快进入派生声明（derived claim）维护，非紧急的整理和合并则可以延后处理。

这种方式受到 [LightMem](https://arxiv.org/abs/2510.18866) 中缓冲、阈值触发和离线整理思路的启发。目前只将它作为一种可能的工程选择，具体处理时机仍由后续实现和实验决定。

## 4. 评测方向

评测需要同时观察外部效用和内部维护行为。

### 4.1 外部效用

- **LoCoMo**：观察多跳问题（multi-hop）、时间问题（temporal）和基础事实召回；
- **LongMemEval-S**：观察知识更新（knowledge update）、跨会话推理（multi-session reasoning）、时间推理（temporal reasoning）和偏好使用；
- **MEME**：观察删除（deletion）和级联（cascade）等更接近动态状态维护的问题。

这些数据集能够说明系统是否具有实际价值，但不能单独证明派生声明（derived claim）的维护过程正确。

### 4.2 内部维护行为

我们还需要直接观察事实变化后，记忆内部发生了什么：

- 相关派生声明（derived claim）是否被重新判断；
- 所有依据失效后，陈旧结论是否仍然残留；
- 出现旧依据之外的新反例时，系统能否发现影响；
- 与变化内容相似但没有真实依赖的记忆是否保持稳定；
- 多轮更新后，局部维护（local maintenance）是否逐渐偏离重新构建的结果。

这些行为可以通过少量人工设计或程序生成的案例进行研究，具体形式和规模根据实现进展决定。

除了最终问答准确率（question-answering accuracy），还值得观察陈旧结论、错误删除、无关修改、证据追溯和维护成本。HaluMem 是否加入，以及如何使用，也可以根据实现结果再决定。

对比方法同样不需要现在固定成最终名单。完整上下文（long context）、朴素检索增强生成（naive retrieval-augmented generation）、事实型记忆、语义局部重写和全量重建，分别提供了不同角度的参照。正式基线（baseline）和消融实验（ablation study）应随着方法逐渐清晰再确定。

## 5. 实现中需要逐步回答的问题

下面的问题不应由当前文档一次性决定：

- 什么样的高层结论值得保存为派生声明（derived claim）？
- 派生声明（derived claim）应该多具体，才能既有复用价值，又不容易过时？
- 成立依据（justification）应如何表达，才能兼顾准确性、可解释性和成本？
- 如何区分真正的更新依赖（update dependency）与普通语义相关性（semantic relatedness）？
- 新事实到来时，应该检查多大的候选范围？
- 什么时候应该修改派生声明（derived claim），什么时候只需改变状态或适用范围？
- 派生声明（derived claim）和原子事实（atomic fact）应如何共同参与检索？
- 写入阶段增加的推理成本，能否在后续重复查询中得到回报？

更合适的推进方式是：先建立能够运行的简单闭环，用具体案例观察记忆如何形成、变化和被检索，再根据真实失败增加必要机制。

如果简单表示已经能够解决主要问题，就没有必要引入复杂结构。如果新反例经常无法被发现，再考虑更强的候选发现。如果成立依据（justification）经常不可靠，再重点研究依据形成和验证。

方法应由实验现象和失败案例推动，而不是由预先设计的模块数量推动。

---

## 6. 当前最核心的研究表达

OurMem 的核心不是实体图、事件图或更复杂的摘要结构，而是：

> **将高层记忆从“生成后静置的一段文本”，变成“具有显式成立依据（explicit justification）、能够随底层事实变化而持续维护的派生知识（derived knowledge）”。**

我们最终希望理解的是：

\[
\boxed{
事实发生变化时，
哪些结论应该改变，
哪些结论仍然成立，
哪些记忆必须保持不动。
}
\]

这也是后续实现、实验和方法迭代始终需要围绕的中心问题。
