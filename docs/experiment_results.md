# 实验进度与结果：ICLR 2027 冻结方案

冻结日期：2026-09-08。**本文件是唯一执行与结果登记入口；不再扩充本轮数据集、模型或基线名单。** 原版保存在 [归档](archive/experiment_results_before_freeze_20260908_050208.md)，旧 `refine-logs/` 方案不是当前执行标准。

这是方法与实验范围的冻结，不表示所有适配代码或环境已经完成。先完成下列准备，再按清单执行；本次规划没有启动、停止或修改任何实验进程。没有一个固定对手数量或分数保证录用。

## 1. 论文要证明什么

核心主张：上游事实变化后，显式依据支持的派生记忆能更可靠地更新下游状态，或在没有可靠新值时保持未知。
辅助主张：这项收益来自派生记忆与依赖定位，而不仅是更强的回答模型、更多检索内容或读取时临时推理。
通用效用：在真实长期对话任务上仍有可用价值；不预设全部分类第一，不宣称最低成本、无限层推理或所有记忆系统全面领先。

**证据主线固定：MEME 验证机制，LoCoMo 验证通用效用，MAB 作为开发暴露的补充。**
选择 LightMem 是因为它有两种当前骨干模型的公开 LoCoMo 复现路径，且直接检验我们的成本取舍；不是因为其公开成绩低于某次 OurMem 旧结果。EverMemOS 的论文版本/现实现差异及专用检索组件核对尚未闭环，本轮不将其作为阻断项，但仍在相关工作中认真讨论，不忽略其已发表结果。

### 2.1 固定输入与评分

- **MEME**：保留全部历史和真实前后观察点。先回答变化前问题，再摄入变化，再回答变化后问题。黄金实体、任务类别、跳数、依赖和答案只在评测侧使用。
- **MEME主指标**：官方六类和问题加权总体；正文突出级联（Cascade）与信息缺失（Absence），另报1/2跳、领域与变化前正确率。级联、信息缺失和删除沿用官方平凡通过过滤（trivial-pass filtering）：只把前后都正确的情况计为真实通过，分母保持全部该类题目。精确召回使用官方确定性实现，不一律换成模型评判。
- **LoCoMo**：仅对话正文、具名说话者、公开会话时间及统一的 `blip_caption`。**不使用图片检索词 `query`**、人工事件摘要或预生成观察。各方法使用同一清洗输入；旧有query进入记忆的构建必须重做，不能只在回答时删字段。
- **LoCoMo主指标**：总体与四类统一模型评判准确率；同时保留固定官方代码的F1，词面F1不冒充准确率。全10对话，不裁历史、不挑子类；第5类不运行。BLEU可复用答案离线计算，但不列为本轮交付要求。
- **MAB**：6k两组完整输入，每组456行含标题及编号事实；遵守公开“较大序号优先”，不按现实常识改事实。确定性官方子串匹配评分；不使用模型评判。
- 技术失败按事先规则计零并单列原因，不能删题。基础构建未完成、缺少终态时不填写完整主成绩。维护未决和语义未知分开。

### 2.2 固定模型与基线使用原则

| 项目 | 冻结规则 |
|---|---|
| GPT组构建、内部推理与回答 | gpt-4o-mini |
| 千问组构建、内部推理与回答 | qwen3-30b-a3b-instruct-2507 |
| 需要模型评分的任务 | 两组统一 gpt-4o-2024-11-20，温度0，固定原评分提示 |
| 通用语义嵌入 | text-embedding-3-small；若专用模型是方法不可替代部分，保留并披露，不随意删掉 |
| 输入与回答协议 | 数据集内统一允许的信息和回答提示；必要格式包装留档 |
| 各方法温度、检索数量、更新阈值 | 优先固定论文实验推荐；没有任务推荐时使用官方实验入口默认，不能把系统函数默认误作论文推荐 |
| 证据与上下文预算 | **不给基线额外套用8000证据或16000输入上限。**保留方法固有配置，记录实际长度。OurMem自身使用冻结配置，不因为对手不同而暗中改动 |
| 服务商适配 | 输出1000导致已知截断等兼容问题允许明确修复并记录；不以缺损JSON、空回退或删输入把对手跑弱 |

| 骨干模型之外的资源 | LightMem保留官方预压缩模型，单列CPU/GPU时间与显存；没有GPU时先检查CPU吞吐，不删掉压缩模块冒充LightMem |

### 2.3 每个基线怎样用

- **Full Context**：整个观察点允许看到的原始历史直接回答，不预先抽取/总结，不伪装成8k等预算方法。超出真实模型窗口必须显式报告，不能静默截短。
- **Dense RAG（MEME）**：官方原生分块和检索入口，text-embedding-3-small，官方默认top-k=5，无生成式记忆维护；不另做BM25重复对照。
- **Hybrid RAG（LoCoMo）**：原文语义检索＋BM25，以RRF融合，取20个不同原文候选；来源切分复用OurMem原文索引规则。不抽取事实、不形成派生、不做OurMem更新与补检。固定该强基础对照，不根据结果调参。
- **A-MEM（LoCoMo/MAB）**：使用已经核对的官方论文实验入口默认：检索10、演化邻居5、刷新阈值100、内部温度0.7；保留当前已披露的模型统一、标识修复、无额外输入/证据上限和输出完整性适配。不恢复导致Qwen截断的1000输出硬限制。与原论文配置不完全相同，必须注明。
- **Mem0（MEME/LoCoMo）**：固定官方基础向量版本，不增加Mem0-Graph。MEME优先复用其官方评测仓库对Mem0的适配，LoCoMo复用MemBase已有方法层；两者必须核对为同一Mem0算法版本/参数，不能只因名称相同就视为同方法。全部原生提取与更新调用入账。
- **MD-flat（仅MEME）**：使用已固定官方原始提示与文件工具流程，不使用SIMBA优化版，不给它增加OurMem的依赖结构。
- **LightMem（仅LoCoMo）**：固定正式论文对应版本，执行完整的预压缩、主题分段和离线更新，不只跑在线简化版。正式表3已有设置中，GPT采用压缩保留率0.8、短期缓冲阈值768词元；Qwen采用0.8、1024词元，完成离线更新后评分。其他参数依该版本官方脚本；不在本轮扫压缩率/阈值。论文设置与可执行代码若不一致必须先登记核对，不自行猜测。

## 3. 核心消融：固定两项，不再增加开关名单

T4仅用GPT组、MEME `meme40` 的相同40情节/277个变化后问题；所有变化前检查仍执行。完整OurMem复用T1-G对应情节，不重跑。只新增以下两个变体。

| 版本 | 改变 | 必须保留 | 检验 |
|---|---|---|---|
| 仅事实（Fact-only） | 禁止保存派生结论及其派生维护 | 原文、事实抽取与协调、版本/时间/删除、相同读取与回答 | 写入时派生是否优于事实记忆加读取时推理 |
| 语义定位维护（Semantic-target repair） | 只用语义/BM25/时间候选选择模型修复目标，不沿反向依赖定位目标 | 相同派生、证据验证、修复动作、读取与可用性规则 | 显式依赖定位是否优于仅凭相关性找目标 |
| 完整OurMem | 原方法 | — | 参照 |

共同报告：六类准确率与总体；正文重点呈现级联、信息缺失、总体、构建/维护调用和词元。
语义定位变体不得通过待修复列表、全库失效清单或依赖闭包偷偷获得同一组修复目标；可用性检查可保留，但目标选择必须独立可审计。候选数量/调用预算上限与完整方法一致，实际调用量另列。
仅事实必须真正禁用派生，不把某一个生成上限设零当作等价实现。两种变体都从原始对话独立构建，不从完整方法数据库删除字段伪造。
当前读取若改变，所有消融都使用同一冻结读取器。本轮不新增复杂关联读取机制，也不单独铺开读取模型/提示/深度消融。

## 4. 三项分析：直接说明机制、代价与可靠性

### T5：提问前状态检查
使用 `audit20` 的20情节（10＋10），包括32个级联、26个信息缺失变化后问题。各变体在变化后刷新完成、第一次变化后提问前保存快照，之后只读核对，不允许通过问题触发补写。
预先按评测侧目标检查：正确新值/有依据未知是否已表示；旧值是否仍被标成当前可用；是否未决/找不到。统计完整目标分母。对已物化派生另外核对支持充分性并同时报覆盖，防止只挑成功主张。
这不是新基准，也不是MEME官方指标。标准答案与依赖只用于事后核对，不进入构建、检索或目标选择。不能把读时临时推理的正确答案全部归因于写入维护。
展示1个成功案例＋1个失败案例，选样规则和覆盖范围说明清楚。

### T6：成本与可靠性
从同一主实验和消融运行记录构建/维护、检索/内部读取推理、回答的模型调用、输入输出词元、嵌入及工具调用、累计阶段时间、查询P50/P95、完成数、技术失败数。评分调用单独统计。
主文给紧凑成本表和准确率—实际词元散点；不新增2k/8k强制裁剪对照，不为追求等预算破坏原生方法。
所有失败尝试计入成本；未知用量标未知。不能将最后一次成功耗时冒充累计时间。对LightMem计入本地压缩计算；对其他方法计入数据库/编码器/重排序等实耗。
OurMem此前高成本是风险，论文不预设效率优于LightMem。高成本下只有明确机制收益才有合理取舍，不以更多调用换来微小提升就宣称优势。

### T7：最小重复与评分核对
GPT组MEME使用 `repeat10` 的固定10情节（5＋5），**完整OurMem与MD-flat各做3次独立构建/检索/回答**。主表匹配的首次运行可作第1次，因此只增加4次×10情节，不做全部方法、两种模型的三次全量重复。
报告总体、级联、信息缺失的三次均值和标准差；这是子集上的模型随机性检查，不代替全量结果。
在主表/消融上按MEME情节、LoCoMo对话进行2000次配对自助采样（paired bootstrap），报告差值95%区间。MAB共享上下文，不把200题当作200个独立用户。
固定抽查50个模型评分样例，按任务和方法分层覆盖；重点核对未知/删除是否被技术占位答案误判为成功。发现系统性评分问题时，基于固定规则修复并对所有相关方法一致重评分；不只修有利于OurMem的题。

### 准备状态与资源
现有MEME原生Full Context/Dense/MD-flat入口和MemBase A-MEM/Mem0代码可复用；但有代码不等于已接通本文协议。当前统一官方入口尚未开放LoCoMo的A-MEM/Mem0/LightMem，也未开放MEME的Mem0，需完成薄适配；LightMem尚需接入及独立依赖准备。不得假称这些已可直接运行。
不改写对手算法、不自行重写LightMem压缩、不绕过MEME观察点，也不复用旧含图像query的LoCoMo记忆。
正式配置冻结后，首批只检查运行完整性、吞吐和用量，不依据正式正确率调方法。先用独立合成场景调试。若必须在正式样本做语义调参，明确记录开发暴露，并由用户批准修订实验范围；不能悄悄排除困难样本。

## 6. 本轮明确不做

- EverMemOS、StructMem、MemoryOS、LangMem及其他额外记忆系统的新增实验。
- LongMemEval-S、MEME无填充/128k、MAB32k及以上、自建数据集。
- 全量多随机种子、模型规模/嵌入模型扫描、层数/多路径逐项消融、额外提示优化或训练。
- 对基线统一施加8000最终证据上限；重复改回原生截断配置。
- MAB再补BM25/Full Context以扩表；其价值不如完成MEME机制证据。
- 因为某个对手公开成绩高而排除，或因分数低而纳入；本文选择由任务相关性、代码可复现性和时间共同确定。

若最终证据不支持核心机制，不通过删除负结果、缩分母或增加简单基线掩盖。范围冻结不是强行冻结“正结果”，也不是录用保证。
