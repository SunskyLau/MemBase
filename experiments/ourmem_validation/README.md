# OurMem V5 实现与验证记录

本轮在原 OurMem 上完成迁移，没有另建 V5 平行实现。旧研究文档、数据和历史实验结果保留；没有提交或推送代码。

## 已落地

统一的来源、记忆版本与依赖；每样本 SQLite；NumPy 精确向量检索与 BM25；最多五层的多前提、多路径派生；统一时间、关闭、纠错、删除和历史读取语义；可恢复写入与批量维护；完整证据读取、集合分页、程序计算及有限覆盖记录。

LoCoMo、LongMemEval-S、MemoryAgentBench 和 MEME 已接入各自固定版本的输入与官方评分协议，并提供独立薄 Shell 入口、三种运行范围、干运行、配置和源码指纹检查及续跑。其他基线仍使用原运行器。依赖已在现有 `membase-ourmem` 环境补齐并固定，`pip check` 无冲突。

模块导航见 [OurMem README](../../membase/ourmem/README.md)，参数见 [OurMemConfig](../../membase/configs/ourmem.py)。

## 离线验证

最终 `python -m unittest discover -s tests -q`：**236 项通过**。包含多路径、五层与超限、级联维护、确认与复述、历史/删除隔离、重放与重启、向量缓存、集合覆盖、证据预算、调用重试、跨样本与变化前后隔离、评分缺项和不一致续跑。

四套数据哈希与官方提交检查通过；四组运行脚本、12 种模式和任意工作目录调用检查通过。干运行不调用模型、不创建记忆数据库。`git diff --check` 通过。

## 受限真实验证

使用本地已有接口配置。所有尝试、重试、回答及评判共用 `runs/v5_acceptance/request_budget.sqlite3`，没有通过新尝试名称重置预算。最终累计 **55 次语言模型请求、19 次嵌入请求**，低于 100/20 上限。接口报告的累计词元为 182,887；另有一次被拒绝请求未返回用量，不能将其费用假定为零。

| 记录 | 实际结果 |
| --- | --- |
| `synthetic_01` | 初始回答正确，但计算字段缺失导致未完成；更新阶段因模型擅自返回非调度修复目标而中止。 |
| `synthetic_02` | 初始与更新后回答均正确且处理完成；删除维护阶段因验证提示缺少 JSON 声明被接口拒绝。 |
| `synthetic_03` | 从失败检查点明确续跑，复用前两步原答案。删除后原值 300 未出现在回答及后续模型输入中，但模型误把酒店距离 2000 当成父亲步行上限，问答检查失败。 |
| `deletion_read_replay_01` | 使用上一条实际检索证据原样进行读取阶段复验；修正对象/属性约束后，明确回答缺少该信息，没有猜测数值。仅属定点复验。 |
| `real_inputs_01` | LoCoMo 抽取通过；LongMemEval 出现时间类别与计划模态混填及非法上下文引用，按上限中止。 |
| `real_inputs_02` | 四数据集首批实际消息均通过抽取结构与原文定位校验，没有读取正式问题或答案。 |

最终真实接入范围：LoCoMo 8 条消息、3 条抽取结果；LongMemEval-S 2 条消息、10 条结果；MemoryAgentBench 8 条消息、7 条结果；MEME 8 条消息、7 条结果，未解析项均为 0。这只能验证接入、结构和出处，不证明事实抽取完整或四数据集准确率。

发现的问题已修复并加入离线回归：修复目标必须与调度清单一致；计算操作数必须显式提供；自定义结构输出统一声明 JSON；重试保留最近失败结果；删除必须提供不含被删值的非空主题；时间类别与模态分开；读取不得用相似对象的数值替代所问属性。调用约定参考 [OpenAI 官方结构输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)，官方评分提示未改写。

## 仍未验证

**修复后的完整删除链路尚未从原始输入重新验证。** 当前完成的是底层删除隔离回归、一次真实失败定位及读取阶段定点复验，不能合并声称整条真实链路已全部通过。嵌入额度仅余一次，不足以再跑完整重建流程，本轮没有扩额。

没有运行四数据集的全量付费实验，没有产生可报告的正式准确率、论文结论、最优参数或准确率—成本比较。专用机制消融、机制诊断汇总和置信区间仍需后续实验工作。

## 运行

进入相应 `experiments/ourmem_*` 目录，编辑已忽略提交的 `run.sh` 顶部配置，先执行 `./run.sh --dry-run`，核对后手动执行 `./run.sh`。无密钥模板为同目录 `run.example.sh`。正式入口默认不限制调用总数；如需限额，请配置两个请求上限和共用账本路径。

`scripts/validate_ourmem.py` 保存独立短场景及 `--real-data-extraction` 接入检查。`--resume-attempt` 只用于明确记录的短场景技术失败继续，不是允许正式实验在更换代码后混合续跑的开关。详细配置、源码指纹、原始请求、阶段结果及失败信息均保存在上述各尝试目录。
